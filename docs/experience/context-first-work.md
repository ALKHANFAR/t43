## مهمة تنتهي أم موظف دائم؟

ليس سؤالًا إلزاميًا في أول رسالة. يستنتج المسار من الطلب الصريح:

- «جهز عقد هذا العميل» = مهمة واحدة ذات نتيجة ونهاية؛ لا تنشئ موظفًا أو نشر schedule لمجرد بدء العمل.
- «كل طلب جديد جهز له عقد» = عمل متكرر؛ يحتفظ بموظف وطريقة عمل وتوقيت/حدث وتشغيل وإيقاف.
- إذا لم يغير الفرق طريقة التنفيذ الآن، ابدأ تجهيز النتيجة. إذا احتاج نشرًا دائمًا، اسأل: «هذه المرة، أو على كل طلب جديد؟» مرة واحدة قبل النشر.
- تغيير الرأي من مهمة إلى موظف يستعمل المسودة والسياق القائمين؛ لا يكرر إدخال الشركة أو ربط الحساب.

## مثال محادثة مبني على حالة الخادم

النصوص أمثلة مقترحة لا شاشات منشورة:

1. طلب: «جهز عقد العميل الجديد». تقرأ سيادة الشركة والطلب والاتصالات المتاحة فعليًا؛ تعرض داخل رسالة قصيرة «أراجع بيانات الشركة وطلب العميل» فقط عند بدء القراءة الحقيقي، مع المصدر في التفاصيل.
2. إن وجدت بيانات وقالبًا معتمدًا: «بيانات الشركة محفوظة. سأجهز العقد من قالبك». لا تسأل الاسم والعنوان والأسعار من جديد.
3. إن غاب القالب الذي يحدد البنود: «أرسل قالب العقد الذي نعتمده»؛ هذا يمنع التنفيذ الصحيح. لا تسأل عشر حقول دفعة واحدة لمجرد أنها فارغة.
4. إن كان Google Sheets محفوظًا وتحتاج المهمة قراءة منه: تستعمل الاتصال القائم بعد guard؛ لا تعيد OAuth لأن المستخدم دخل شاشة جديدة. إن كان تفويض MCP مؤجلًا: تظهر «المسودة محفوظة؛ التنفيذ ينتظر السماح باستخدام أدوات الشركة»، ويظل الطلب قابلاً للاستئناف. لا تمنح الإذن أو تدعي قراءة المزود.
5. تعرض «أبحث عن طلب العميل في Google Sheets» مع شعار الأداة عند tool-call الحقيقي. عند الفشل: «لم أتمكن من قراءة الطلب» وفعل تالٍ محدد من سبب موثق. لا تعرض أداة بحث وهمية أو reasoning مصطنع.
6. تنتهي المهمة برابط/معرف عقد ونتيجة قراءة مستقلة أو تقول «مسودة للمراجعة» بحسب الدليل. الموظف الدائم يظهر طلبه الأصلي، عمله الجاري، آخر نتيجة، وإيقافه في محادثته الخاصة.

## خطة أقل كود

1. **عقد سياق واحد:** يراجع مالك server projection الحالي ويضيف key/observedAt وفصل confirmed/observed وknown/missing فقط، دون قاعدة معرفة جديدة. missing تُحسب لمتطلبات المهمة الحالية، لا profile completeness عام.
2. **توجيه قائم:** يستفيد من draftOnly/currentDraft/selectedEmployee؛ يوضح one-time مقابل ongoing قبل أول action مختلف الأثر. لا ينشئ محرك planner ثانياً أو role ثابت لكل كلمة.
3. **جرد اتصالات عند الطلب:** use service.list الحالي بعد session/project guard. أعط النموذج summary منزوعة الأسرار (piece/status/exclusive)، مع وقت القراءة؛ تفاصيل الأفعال وprops تأتي native MCP حين يسمح المستخدم. لا تمنح التوكن المؤجل ولا تطلب الربط مرتين.
4. **عمل مرئي من receipts:** اربط UI القائمة بمراحل request/work/tool الحالية. shown progress يأتي حدث server، لا setTimeout، ولا علامة اكتمال بلا readback.
5. **سؤال واحد يمنع خطأ حقيقي:** لا تسأل known أو لا يؤثر الآن. إن تعارض اتصالان/عميلان يحتاج التنفيذ الاختيار، أظهر الاختيار المحدد؛ ليست حرية للنموذج أن يخمن هوية العميل.
6. **إثبات قبول:** طلبان متتابعان يستعملان saved context/connection بلا إعادة أسئلة؛ مهمة واحدة لا تنشئ employee دائمًا؛ ongoing يثبت native Flow/trigger/version/run؛ إلغاء/مهلة/فشل يستأنف بلا ازدواج؛ شركتان لا تتبادلان context/connection/flow.
