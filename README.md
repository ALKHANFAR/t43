# Siyadah AI

هذا مستودع واجهة سيادة وخادمها الحالي. سيادة تملك الحسابات والصلاحيات وواجهة العميل وقاعدة بياناته، وتستخدم Activepieces للتنفيذ خلف الخادم. هذا المستودع هو مرجع الكود المعتمد لهذا المسار؛ `77766` مستبعد بقرار المؤسس. ابدأ من [خريطة الأجزاء](ARCHITECTURE.md) و[فهرس الميزات](FEATURE_INDEX.md)، ثم تحقق من الفرع والنشر الفعليين قبل أي تعديل.

| المسار | المحتوى |
|---|---|
| `/` | الموقع: `index.html` (EN) · `ar.html` (AR) · `integrations.html` · `demo.html` · `privacy.html` |
| `/app` | واجهة المنصة: `onboard.html` (الإعداد الأول) · `chat.html` (التطبيق) |
| `server.mjs` و`lib/` | API سيادة، جلسة الشركة، PostgreSQL وربط أدوات التنفيذ |
| `migrations/` | تغييرات قاعدة البيانات التي تُطبّق قبل نشر الخدمة |
| `STANDARDS.md` | تقرير المعايير: WCAG AA، HTML صالح، رؤوس الأمان، PDPL/GDPR، SEO |

## النشر

خدمة التطبيق `siyadah-direct-ui` تعمل في Railway من فرع `codex/abo-38-isolation-gate-20261001` عند قراءة 2 أكتوبر 2026؛ تحقق من SHA والنشر الحيين قبل دمج لاحق. `railway.json` يشغّل ترحيل المخطط قبل بدء الخدمة. ملفات الجذر في هذا المستودع ليست بالضرورة الموقع العام: `siyadah-ai.com` منشور منفصلًا لدى LWS، ونسخة LWS العربية والإنجليزية لم تُحدّث بعد إلى API قائمة الانتظار الجديد. رفع HTML إلى GitHub Pages لا يشغّل `server.mjs` أو قاعدة البيانات.

## التسجيلات
API قائمة الوصول المبكر في سيادة يحفظ الطلب في PostgreSQL: `POST /siyadah-api/v1/waitlist`. تأكد من حالة نموذج الموقع العام لدى LWS بشكل مستقل؛ عند قراءة 2 أكتوبر 2026 كان لا يزال يستخدم webhook قديمًا. دليل الإصدار وحالة Google في [ABO-62](docs/google-review/release-gates.md).

## شات التطبيق الحقيقي

`app/chat.js` يطلب مسارات `/siyadah-api` من خادم t43؛ لا يتصل بـ Activepieces مباشرة. الخادم يتحقق من جلسة العميل وشركته، ثم يربط مشروع الشركة وأدواتها. يمكن ضبط `window.SIYADAH_CHAT_GATEWAY` عند الحاجة؛ لا تجعل عنوان تنفيذ أو مفتاحًا يظهر للمتصفح.

الرد يستطيع حمل `SiyadahFlowAcceptanceV1` أو `SiyadahFlowAcceptanceV2`، وتعرض الواجهة ما تم إثباته وما
بقي من عشر بوابات مستقلة. تعرض الواجهة «المسودة جاهزة 10/10» عندما تكتمل
المسودة المعطلة وتصبح جاهزة لربط الحسابات. ويظل إثبات التشغيل والأثر منفصلاً؛
لا يظهر وصف «نتيجة تشغيل مثبتة 10/10» إلا عندما يعيد الخادم
`can_claim_10_of_10: true` بعد إثبات التشغيل ونتيجة المزود والأثر التجاري.

## ملاحظات
- `pieces.js` في الجذر كتالوج عرض للأدوات؛ تحقق من قدرات الأداة واتصال الشركة في الخادم قبل عرضها كقابلة للتنفيذ.
- الخطوط مستضافة محليًا في `fonts/` (لا طلبات لـ Google Fonts).
- `.htaccess` يعمل على Apache فقط (cPanel). على GitHub Pages يُتجاهل بلا ضرر.
