# مثال تصميم لمساحة موظف سيادة

تصحيح اتجاه 8 أكتوبر: الموظف هو أساس التجربة، والأدوات تفاصيل طريقة عمله. هذا مثال تصميم لدور «متابعة العملاء» وليس موظفًا مُنشأً أو متصلًا بحساب حقيقي، وليس واجهة الإنتاج.

## ما يعمل فعليًا في المثال

- حفظ نص تكليف في ذاكرة الصفحة، فتحه وتعديله، والعودة من السجل.
- حفظ توجيهات محلية داخل «طريقة العمل»؛ أدوات توضيحية قابلة للبحث داخل التفاصيل فقط.
- النتائج فارغة وصريحة: لا تنفيذ ولا قراءة حساب ولا مخرج مزود.
- اتجاه RTL/LTR، قائمة الهاتف، لوحة مفاتيح وتركيز واضح.

أُزيلت مؤقتات التشغيل والمسار المحاكى والنتائج الثابتة واقتراح الأدوات في مربع الكتابة. لا API أو نموذج أو إنشاء موظف. عبارة الحفظ لا تعني إرسالًا أو تنفيذًا. الحفظ في ذاكرة الصفحة ويزول عند إعادة تحميلها.

افتح `siyadah-chat-experience-v2.html` عبر خادم ملفات محلي. الأصل في هذا الفرع معاينة مستقلة؛ لم تُعدل ملفات app/server. خط الجهاز Tahoma/Arial، زر بنفسجي، وشعار سيادة الموجود. روابط شعارات الأدوات من الكتالوج الموجود عبر CDN؛ عدم تحميلها لا يؤثر بحفظ التكليف. مراجع21st السابقة كانت للبحث فقط، لا يوجد ادعاء تثبيت مكون React الأصلي أو اعتماد التصميم النهائي.

## التحقق

ثلاثة اختبارات سلوك: منع API/mockedtimers/mخرجات المزود، تعديل التكليف مع حفظ المسودة عبر التنقل، والأدوات تفاصيل ثانوية والتوجيهات محلية. فحص HTML وJS وfeature index. Chrome1440×960 و390×844: حفظ/تعديل التكليف، نتائج فارغة، composer ظاهر وبلا تجاوز أفقي. اللقطات خارج المستودع في/tmp وهي دليل تصميم فقط.
